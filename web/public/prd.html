Deep Thinking

Architecture Rationale — Why Every Decision Was Made

Every architectural choice in ChainPulse was made to solve a specific problem. Understanding the why behind each decision is what makes this a production system instead of a tutorial project.

🧠

Why Go Over Rust, TypeScript, or Python?

This project targets four JDs simultaneously: Lightning Labs (Go-native org, LND is Go), Blackwing (high-throughput trading infra), Zerion (multi-chain wallet backend), and a Senior Lead Backend role (production Go). Go is the lingua franca of blockchain infrastructure — Geth, Prysm, Cosmos SDK, LND are all Go. It compiles to a single static binary, has first-class concurrency via goroutines, and the go-ethereum libraries (abigen, ethclient) are battle-tested in production at every major blockchain company. Rust would be faster but narrows the audience. TypeScript would be easier but signals "frontend dev doing backend." Go says "I build infrastructure."

⚡

Why Kafka Instead of Direct Database Writes?

The naive approach: listen to blocks → decode events → write to database. This breaks at scale for three reasons. (1) Backpressure — if ClickHouse has a slow write, the ingestion goroutine blocks and misses the next block. Kafka decouples producer from consumer: ingestion never waits for storage. (2) Replay — if you add a new protocol decoder, you need to reprocess historical blocks. With Kafka retention, you replay from any offset without re-fetching from RPC. (3) Fan-out — the same raw event stream feeds the position aggregator, the balance tracker, AND the real-time WebSocket feed. Without Kafka, you'd need to duplicate decoding logic in three places. The Kafka topic structure (raw_events, decoded_events, positions_update) mirrors the processing stages exactly.

🗄️

Why ClickHouse Over PostgreSQL or MongoDB?

Blockchain indexers have a specific data profile: append-heavy writes, analytical reads, time-series queries. "Show me all USDC transfers over $10K in the last 24 hours across 4 chains" is a scan over millions of rows with filters — exactly what columnar databases optimize for. PostgreSQL handles this at small scale but degrades past 100M rows. MongoDB handles flexible schemas but is terrible at analytical aggregations. ClickHouse processes 1B+ rows per second on analytical queries, compresses columnar data 10-20x, and handles the append-only write pattern natively via MergeTree engines. The trade-off: no ACID transactions, no UPDATE/DELETE (append-only). For an indexer, this is fine — blockchain data is immutable.

🤖

Why an MCP Server? What Problem Does It Solve?

This is the Lightning Labs differentiator. An MCP (Model Context Protocol) server exposes on-chain data as AI agent tools. Without it, an AI agent that wants to check a wallet's DeFi positions needs to: (1) know the Aave V3 contract address, (2) construct the right ABI call, (3) decode the response, (4) repeat for every protocol on every chain. With the MCP server, the agent calls get_wallet_positions("0x...") and gets a structured JSON response with all positions across all chains. The MCP server is the translation layer between "human question" and "on-chain data query." This is exactly what Lightning Labs means by "agent-facing tooling" and "agentic workflows" in their JD.

🔄

Why Redis Sits Between ClickHouse and the API?

ClickHouse excels at analytical queries but has higher latency on point lookups (single wallet balance, single token price). The API needs sub-50ms response times for "what tokens does 0x... hold?" — a point lookup, not an analytical scan. Redis caches the hot data: current wallet positions, recent token prices, active DeFi positions. Cache invalidation is event-driven: when the processor writes a new position to ClickHouse, it simultaneously updates the Redis cache via Kafka consumer. This gives you ClickHouse's analytical power for complex queries AND Redis's speed for simple lookups — without the API layer needing to know which backend to hit (the cache-aside pattern handles this transparently).

🏗️

Why Separate Binaries Instead of One Monolith?

Unlike Charon (where latency between components matters), ChainPulse processes are pipeline stages with different scaling profiles. The indexer is I/O-bound (waiting on RPC). The processor is CPU-bound (decoding ABIs, aggregating positions). The API is connection-bound (serving HTTP clients). A single binary forces all three to share the same goroutine pool and memory space. Separate binaries let you run 1 indexer, 3 processors (one per chain group), and 2 API servers behind a load balancer. Kafka is the glue — each binary is a Kafka producer or consumer. Docker Compose runs them as a stack locally; Kubernetes scales them independently in production.

Section 01

System Overview & Design Philosophy

ChainPulse is a production-grade multi-chain blockchain indexer that ingests, decodes, and aggregates on-chain data — then exposes it through REST/gRPC APIs for dashboards and an MCP server for AI agents. It answers questions like "What are all open Aave borrow positions for this wallet across 4 chains?" in under 50ms.

Core Design Principles

Multi-Chain Native

Concurrent goroutines per chain with independent WebSocket connections, backpressure handling, and automatic reconnection with exponential backoff.

Pipeline Architecture

Kafka-backed: ingestion → decoding → aggregation → storage. Each stage is independently scalable. Replay any time window without re-fetching from RPC.

Protocol-Agnostic Decoders

Adding a new DeFi protocol is one Go interface implementation. The core pipeline doesn't change. Uniswap, Aave, Compound, ERC-20 ship on day one.

AI-Agent Ready

MCP server exposes every query as a structured tool. Claude, GPT, or any MCP-compatible agent can query live on-chain data without knowing contract ABIs.

Sub-Second Queries

ClickHouse for analytical scans, Redis for hot lookups. p99 query latency under 50ms for wallet positions, under 200ms for cross-chain aggregations.

Why This Topology?

The architecture separates read-heavy (API/MCP — serving queries) from write-heavy (indexer/processor — ingesting blocks). Kafka is the boundary: everything left of Kafka produces events, everything right consumes them. This means you can restart the API server without missing blocks, replay the processor without re-fetching from RPC, and scale each service independently. The MCP server is intentionally a separate binary so it can be deployed alongside an AI agent orchestrator without pulling in the entire indexing stack.

Why Partition by chain_id?

Each Kafka topic is partitioned by chain_id. This guarantees that all events from Arbitrum go to the same partition, maintaining per-chain ordering. A Swap event on Arbitrum block 200M must be processed before a Swap on block 200M+1. Partitioning by chain_id means you can run N consumer instances where each owns a subset of chains — horizontal scaling without losing ordering guarantees. If you partitioned by something else (e.g., contract address), you'd lose the ability to reason about block ordering within a chain.

Go — Chain Listener 
// internal/ingestion/listener.go
package ingestion

import (
    "context"
    "math/big"
    "time"

    "github.com/ethereum/go-ethereum"
    "github.com/ethereum/go-ethereum/core/types"
    "github.com/ethereum/go-ethereum/ethclient"
    "github.com/rs/zerolog/log"
    "github.com/segmentio/kafka-go"
)

type ChainListener struct {
    chainID   uint64
    chainName string
    wsURL     string
    producer  *kafka.Writer
    decoder   *ABIDecoder
}

func (cl *ChainListener) Run(ctx context.Context) error {
    client, err := ethclient.DialContext(ctx, cl.wsURL)
    if err != nil {
        return fmt.Errorf("dial %s: %w", cl.chainName, err)
    }
    defer client.Close()

    log.Info().
        Str("chain", cl.chainName).
        Uint64("chain_id", cl.chainID).
        Msg("connected to WebSocket")

    // Subscribe to new block headers
    headers := make(chan *types.Header)
    sub, err := client.SubscribeNewHead(ctx, headers)
    if err != nil {
        return fmt.Errorf("subscribe %s: %w", cl.chainName, err)
    }

    for {
        select {
        case err := <-sub.Err():
            log.Error().Err(err).Str("chain", cl.chainName).Msg("subscription error")
            return cl.reconnect(ctx) // exponential backoff reconnection

        case header := <-headers:
            start := time.Now()

            // Fetch all logs for this block
            blockNum := header.Number
            query := ethereum.FilterQuery{
                FromBlock: blockNum,
                ToBlock:   blockNum,
            }
            logs, err := client.FilterLogs(ctx, query)
            if err != nil {
                log.Error().Err(err).Uint64("block", blockNum.Uint64()).Msg("filter logs failed")
                continue
            }

            // Decode and publish each log to Kafka
            for _, vLog := range logs {
                event, err := cl.decoder.Decode(cl.chainID, vLog, header.Time)
                if err != nil {
                    continue // skip unrecognized events
                }

                payload, _ := json.Marshal(event)
                cl.producer.WriteMessages(ctx, kafka.Message{
                    Key:   []byte(fmt.Sprintf("%d", cl.chainID)),
                    Value: payload,
                    Topic: "raw_events",
                })
            }

            recordBlockProcessing(cl.chainName, blockNum.Uint64(), time.Since(start))

        case <-ctx.Done():
            return nil
        }
    }
}

// reconnect implements exponential backoff reconnection
func (cl *ChainListener) reconnect(ctx context.Context) error {
    backoff := time.Second
    for attempt := 0; attempt < 10; attempt++ {
        log.Warn().Str("chain", cl.chainName).Dur("backoff", backoff).Msg("reconnecting")
        time.Sleep(backoff)
        if err := cl.Run(ctx); err == nil {
            return nil
        }
        backoff *= 2
        if backoff > 30*time.Second {
            backoff = 30 * time.Second
        }
    }
    return fmt.Errorf("failed to reconnect to %s after 10 attempts", cl.chainName)
}
Go — ABI Decoder 
// internal/ingestion/decoder.go
package ingestion

import (
    "github.com/ethereum/go-ethereum/accounts/abi"
    "github.com/ethereum/go-ethereum/common"
    ethtypes "github.com/ethereum/go-ethereum/core/types"
)

// Well-known event signatures
var (
    ERC20TransferSig = common.HexToHash("0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef")
    UniswapSwapSig   = common.HexToHash("0xc42079f94a6350d7e6235f29174924f928cc2ac818eb64fed8004e115fbcca67")
    AaveBorrowSig    = common.HexToHash("0xb3d084820fb1a9decffb176436bd02558d15fac9b0ddfed8c465bc7359d7dce0")
    AaveRepaySig     = common.HexToHash("0xa534c8dbe71f871f9f3f77571e29fe5e86e1a4e0b063ccf04c85464e48505828")
)

type ABIDecoder struct {
    erc20ABI   abi.ABI
    uniswapABI abi.ABI
    aaveABI    abi.ABI
}

func (d *ABIDecoder) Decode(chainID uint64, vLog ethtypes.Log, blockTime uint64) (*ChainEvent, error) {
    if len(vLog.Topics) == 0 {
        return nil, fmt.Errorf("no topics")
    }

    eventName := "unknown"
    switch vLog.Topics[0] {
    case ERC20TransferSig:
        eventName = "Transfer"
    case UniswapSwapSig:
        eventName = "Swap"
    case AaveBorrowSig:
        eventName = "Borrow"
    case AaveRepaySig:
        eventName = "Repay"
    default:
        return nil, fmt.Errorf("unrecognized event")
    }

    return &ChainEvent{
        ChainID:     chainID,
        BlockNumber: vLog.BlockNumber,
        TxHash:      vLog.TxHash,
        LogIndex:    vLog.Index,
        Contract:    vLog.Address,
        EventName:   eventName,
        RawTopics:   vLog.Topics,
        RawData:     vLog.Data,
        Timestamp:   time.Unix(int64(blockTime), 0),
    }, nil
}

Go — Protocol Decoder Interface 
// internal/processor/decoder.go
package processor

// ProtocolDecoder is the interface every protocol-specific decoder implements.
// Adding a new protocol = implementing this interface. Nothing else changes.
type ProtocolDecoder interface {
    // Name returns the protocol identifier ("uniswap_v3", "aave_v3", "erc20")
    Name() string

    // CanDecode returns true if this decoder handles the given event signature
    CanDecode(eventSig common.Hash) bool

    // Decode transforms a raw ChainEvent into a protocol-specific DecodedEvent
    Decode(event *types.ChainEvent) (*types.DecodedEvent, error)

    // SupportedEvents returns all event signatures this decoder handles
    SupportedEvents() []common.Hash
}
Go — ERC-20 Decoder 
// internal/processor/protocols/erc20.go
package protocols

type ERC20Decoder struct{}

func (d *ERC20Decoder) Name() string { return "erc20" }

func (d *ERC20Decoder) CanDecode(sig common.Hash) bool {
    return sig == ERC20TransferSig || sig == ERC20ApprovalSig
}

func (d *ERC20Decoder) Decode(event *types.ChainEvent) (*types.DecodedEvent, error) {
    switch event.RawTopics[0] {
    case ERC20TransferSig:
        from := common.BytesToAddress(event.RawTopics[1].Bytes())
        to := common.BytesToAddress(event.RawTopics[2].Bytes())
        amount := new(big.Int).SetBytes(event.RawData)

        return &types.DecodedEvent{
            ChainEvent: *event,
            Protocol:   "erc20",
            EventType:  "transfer",
            Params: map[string]interface{}{
                "from":   from.Hex(),
                "to":     to.Hex(),
                "amount": amount.String(),
                "token":  event.Contract.Hex(),
            },
        }, nil
    }
    return nil, fmt.Errorf("unsupported event")
}
Go — Aave V3 Decoder 
// internal/processor/protocols/aave_v3.go
package protocols

type AaveV3Decoder struct {
    poolABI abi.ABI
}

func (d *AaveV3Decoder) Name() string { return "aave_v3" }

func (d *AaveV3Decoder) CanDecode(sig common.Hash) bool {
    return sig == AaveBorrowSig || sig == AaveRepaySig ||
           sig == AaveSupplySig || sig == AaveWithdrawSig ||
           sig == AaveLiquidationSig
}

func (d *AaveV3Decoder) Decode(event *types.ChainEvent) (*types.DecodedEvent, error) {
    switch event.RawTopics[0] {
    case AaveBorrowSig:
        // Decode: Borrow(address reserve, address user, address onBehalfOf,
        //         uint256 amount, uint8 interestRateMode, uint256 borrowRate, uint16 referralCode)
        decoded, err := d.poolABI.Events["Borrow"].Inputs.Unpack(event.RawData)
        if err != nil {
            return nil, err
        }
        reserve := common.BytesToAddress(event.RawTopics[1].Bytes())
        user := common.BytesToAddress(event.RawTopics[2].Bytes())

        return &types.DecodedEvent{
            ChainEvent: *event,
            Protocol:   "aave_v3",
            EventType:  "borrow",
            Params: map[string]interface{}{
                "reserve":    reserve.Hex(),
                "user":       user.Hex(),
                "amount":     decoded[0].(*big.Int).String(),
                "rate_mode":  decoded[1].(uint8),
                "borrow_rate": decoded[2].(*big.Int).String(),
            },
        }, nil
    }
    return nil, fmt.Errorf("unsupported aave event")
}

Position Aggregator

Go — Position Aggregator 
// internal/processor/aggregator.go
package processor

// PositionAggregator maintains a real-time view of wallet positions
// by consuming decoded events and updating ClickHouse + Redis.
type PositionAggregator struct {
    clickhouse *sql.DB
    redis      *redis.Client
    decoders   []ProtocolDecoder
}

func (pa *PositionAggregator) ProcessEvent(event *types.DecodedEvent) error {
    switch event.EventType {
    case "transfer":
        return pa.handleTransfer(event)
    case "borrow":
        return pa.handleBorrow(event)
    case "supply":
        return pa.handleSupply(event)
    case "swap":
        return pa.handleSwap(event)
    }
    return nil
}

func (pa *PositionAggregator) handleTransfer(event *types.DecodedEvent) error {
    from := event.Params["from"].(string)
    to := event.Params["to"].(string)
    amount := event.Params["amount"].(string)
    token := event.Params["token"].(string)

    // Write the raw transfer event to ClickHouse
    _, err := pa.clickhouse.Exec(`
        INSERT INTO token_transfers
        (chain_id, block_number, tx_hash, log_index, token, from_addr, to_addr, amount, timestamp)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)`,
        event.ChainID, event.BlockNumber, event.TxHash.Hex(),
        event.LogIndex, token, from, to, amount, event.Timestamp,
    )
    if err != nil {
        return err
    }

    // Update Redis cache for both wallets
    pa.redis.HIncrBy(ctx, fmt.Sprintf("balance:%s:%d:%s", from, event.ChainID, token), "amount", -amountInt)
    pa.redis.HIncrBy(ctx, fmt.Sprintf("balance:%s:%d:%s", to, event.ChainID, token), "amount", amountInt)

    return nil
}

CREATE MATERIALIZED VIEW wallet_balances_mv
ENGINE = SummingMergeTree()
ORDER BY (chain_id, wallet, token)
AS SELECT
    chain_id,
    to_addr AS wallet,
    token,
    toInt256(amount) AS balance_delta,
    max(timestamp) AS last_updated
FROM token_transfers
GROUP BY chain_id, to_addr, token;

package api

import (
    "github.com/gin-gonic/gin"
    "github.com/prometheus/client_golang/prometheus/promhttp"
)

type Server struct {
    clickhouse *sql.DB
    redis      *redis.Client
    router     *gin.Engine
}

func NewServer(ch *sql.DB, rd *redis.Client) *Server {
    s := &Server{clickhouse: ch, redis: rd}
    s.router = gin.New()
    s.router.Use(gin.Recovery(), s.corsMiddleware(), s.rateLimitMiddleware())

    v1 := s.router.Group("/v1")
    {
        v1.GET("/wallet/:address/positions", s.getWalletPositions)
        v1.GET("/wallet/:address/balances", s.getWalletBalances)
        v1.GET("/wallet/:address/history", s.getWalletHistory)
        v1.GET("/token/:address/transfers", s.getTokenTransfers)
        v1.GET("/protocol/:name/stats", s.getProtocolStats)
        v1.GET("/chain/:id/blocks", s.getChainBlocks)
        v1.GET("/events/stream", s.streamEvents) // WebSocket
    }

    s.router.GET("/metrics", gin.WrapH(promhttp.Handler()))
    s.router.GET("/health", s.healthCheck)

    return s
}

func (s *Server) getWalletPositions(c *gin.Context) {
    address := c.Param("address")
    chainID := c.Query("chain_id") // optional filter

    // Try Redis cache first
    cacheKey := fmt.Sprintf("positions:%s", address)
    cached, err := s.redis.Get(ctx, cacheKey).Result()
    if err == nil {
        c.Data(200, "application/json", []byte(cached))
        return
    }

    // Cache miss → query ClickHouse
    query := `
        SELECT chain_id, protocol, event_type, user_addr, token_a, amount_a, timestamp
        FROM defi_events
        WHERE user_addr = ?
        ORDER BY timestamp DESC
        LIMIT 100`

    rows, err := s.clickhouse.Query(query, address)
    if err != nil {
        c.JSON(500, gin.H{"error": "query failed"})
        return
    }
    defer rows.Close()

    var positions []WalletPosition
    for rows.Next() {
        var p WalletPosition
        rows.Scan(&p.ChainID, &p.Protocol, &p.PositionType,
                   &p.Wallet, &p.Token, &p.Amount, &p.UpdatedAt)
        positions = append(positions, p)
    }

    // Cache for 30 seconds
    data, _ := json.Marshal(positions)
    s.redis.Set(ctx, cacheKey, data, 30*time.Second)

    c.JSON(200, positions)
}

MCP — AI Agent Query Layer

Build the MCP-compliant server that exposes on-chain data as structured tools. Any MCP-compatible AI agent (Claude, GPT) can query wallet positions, token transfers, and protocol stats conversationally.

🤖

What the MCP Server Actually Does

Without ChainPulse's MCP server, an AI agent that wants to answer "What DeFi positions does 0xABC hold across all chains?" needs to: (1) know the Aave V3 pool address on each chain, (2) know the getUserAccountData ABI, (3) make 4+ RPC calls (one per chain), (4) decode the responses, (5) repeat for Compound, Uniswap, etc. With ChainPulse, the agent calls a single MCP tool: get_wallet_positions(wallet: "0xABC") and gets a JSON response with every position across every chain and protocol. The MCP server IS the translation layer between "human-language question" and "multi-chain data query." This is exactly what Lightning Labs means by "agent-facing tooling."

type ToolHandler func(params map[string]interface{}) (interface{}, error)

}

func NewMCPServer(ch *sql.DB, rd *redis.Client) *MCPServer {
    s := &MCPServer{clickhouse: ch, redis: rd, tools: make(map[string]ToolHandler)}

}

// CallTool executes a tool by name with the given parameters
func (s *MCPServer) CallTool(name string, params map[string]interface{}) (interface{}, error) {
    handler, ok := s.tools[name]
    if !ok {
        return nil, fmt.Errorf("unknown tool: %s", name)
    }
    return handler(params)
}

// getWalletPositions returns all DeFi positions for a wallet
func (s *MCPServer) getWalletPositions(params map[string]interface{}) (interface{}, error) {
    wallet := params["wallet"].(string)

    // Try Redis cache first
    cacheKey := fmt.Sprintf("mcp:positions:%s", wallet)
    if cached, err := s.redis.Get(ctx, cacheKey).Result(); err == nil {
        var result []WalletPosition
        json.Unmarshal([]byte(cached), &result)
        return result, nil
    }

    // Query ClickHouse for all positions
    rows, err := s.clickhouse.Query(`
        SELECT chain_id, protocol, event_type, token_a, amount_a, timestamp
        FROM defi_events
        WHERE user_addr = ? AND event_type IN ('supply', 'borrow')
        ORDER BY timestamp DESC
        LIMIT 200`, wallet)
    if err != nil {
        return nil, err
    }
    defer rows.Close()

    var positions []map[string]interface{}
    for rows.Next() {
        var chainID uint64
        var protocol, eventType, token, amount string
        var ts time.Time
        rows.Scan(&chainID, &protocol, &eventType, &token, &amount, &ts)
        positions = append(positions, map[string]interface{}{
            "chain_id":  chainID,
            "protocol":  protocol,
            "type":      eventType,
            "token":     token,
            "amount":    amount,
            "updated":   ts.Format(time.RFC3339),
        })
    }

    // Cache for 60 seconds
    data, _ := json.Marshal(positions)
    s.redis.Set(ctx, cacheKey, data, 60*time.Second)

    return positions, nil
}
